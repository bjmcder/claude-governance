## Findings

### Defect

1. **TEST.5 and TEST.3 sentence 2 conflict with STND.WPROC.9 (no listed pair).** WPROC.9 has each check that the change is able to affect pass before a merge, "other than a check deferred to the release under RSRC.12 and recorded in the unit record"; the WPROC Notes give the same scope. TEST.5 draws a merge at depth 1 or more from fewer tiers, and TEST.3 lets an affected test in an undrawn tier wait for a nearer merge. Both cannot be met at depth 1 or more (at depth 0 every tier is drawn, as WPROC.9 has it). The Notes say the deferral "rests on RSRC.12 in the same way"; RSRC.12 permits it, but WPROC.9 narrows it to the release. Also, WPROC.11 lets an agent merge without the owner only where WPROC.9 is met, so each tier deferral would send the merge to the owner, and TEST.3 records the omission in the run record where WPROC.9 asks the unit record.
   Fix: amend WPROC.9 in the same adoption to read "other than a check deferred under RSRC.12 to a later merge or to the release, and recorded in the unit record". Add to TEST.3 that the unit record SHOULD cite the record of the run. 

### Should-fix

2. **TEST.13 quarantine against WPROC.9.** A quarantined affected test is not passing; WPROC.9 has no exception. Fix: add "or in quarantine under STND.TEST.13" to the amendment of finding 1; cite QA.6 in TEST.13 so that quarantine does not replace restoring a check that the actor's own change broke.
3. **TEST.4 against TEST.5 (internal; STND.CODE.8).** TEST.4 holds new, changed, and last-failed tests and the rows of its table in each selection; TEST.5 draws from the tiers of the depth. A regression test added for a fix under CODE.8 in an undrawn tier falls in both. Fix: TEST.5 sentence 1 adds "except the tests that sentence 2 of STND.TEST.4 holds, which are drawn from every tier"; table rows outside the drawn tiers are omissions under TEST.3.
4. **Deferred checks and AGENT.47 / WPROC.13 (unowned).** A test that TEST.3 omits although the change affects it is a skipped check in the plain sense; AGENT.47 (binding) has the agent state it and WPROC.13 carries it to the release proposal even after the test ran. Fix: TEST.3 sentence 2 adds that the work report states it under AGENT.47 until the test has run, and the release proposal states only a deferral that no run has closed.
5. **"Partial oracle" against NUMER.6, VVUQ.18, and VV.7 (conflict; pair 160, same wording at 157).** The Term counts "agreement of independent implementations" as a partial oracle that "does not give the expected output". NUMER.6 requires oracles "computed without the implementation it judges"; VVUQ.18 ranks an independent implementation among reference oracles. The same device is full in one text and weak in the other. VV.7 also has each test state its reference, which TEST.15 does not. Fix: Term: "...or the agreement of independent implementations other than a reference oracle of NUMER.6"; TEST.15 sentence 1 adds "and state it as the reference of the test (VV.7)".
6. **Hardware as a verdict input (unowned; pairs 14, 18, 316-318, 322-324, 328-330, 334-336, 343, 347, 360, 364).** HW.3 and HW.QPU.3 record, and HW.7, HW.CPU.3, and HW.EMBED.5 confirm, the hardware model, firmware, drivers, runtime libraries, and calibration. The Term Verdict input omits them, TEST.4 has no row for them, and TEST.9 does not record the path, so a reused verdict (TEST.8) could stand across a firmware change. Fix: add them to Verdict input; add a TEST.4 row "Those items of an execution path, or its reference path (HW.15) | each test that runs on the path or compares with it"; add the execution path to the Revision row of TEST.9.
7. **Reseeding outside numerical comparisons (unowned; pair 254).** NUMER.26 binds a comparison of a stochastic result only. TEST.12 fires under the same verdict key, and a redraw changes the key; TEST.11 invites a rerun to test a hypothesis. A generated-input test that passes on a new draw is covered by nothing. Fix: TEST.12 sentence 1 adds "or under a key that differs only in a random seed or a drawn input"; TEST.11 adds "other than a rerun that NUMER.26 bars".
8. **TEST.19 sentence 1 omits a changed expected value (unowned; pairs 283-285, 297, 306).** Renewing a guard's reference, or changing an expected value to fit the output, is the commonest weakening; VVUQ.17 holds it for numerical guards only. Fix: add "changes the expected value or reference of" to the list.
9. **TEST.8 and TEST.9 against BUILD.23 sentence 2 (conflict; no listed pair).** BUILD.23 keeps the outputs of a step that reads a secret out of each cache. TEST.8 lets the verdict of a test that reads a secret stand, and the key (TEST.9 row Reused verdicts) would hold a digest of it, which PRIME.10 bars from a record. Fix: TEST.8 sentence 2 adds "or reads a secret"; the Term Verdict key excludes the value of a secret.
10. **TEST.6 and the release decision (unowned).** WPROC.13 and .14 put the outcome of the checks on the revision into the proposal and record on which the owner decides (WPROC.12). A later run leaves the owner without it. Fix: TEST.6 sentence 1: "before the release record is presented under STND.WPROC.13".
11. **Integration depth is undefined for a parent merged into a descendant (WPROC.6, .8), a merge into a main line, and a release, yet TEST.9 assigns a release a depth (unowned).** Fix: the Term says these have no depth and run under TEST.3 and TEST.6; TEST.9 reads "its integration depth, if a merge".
