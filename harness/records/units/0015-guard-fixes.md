# Unit 0015: guard fixes from the QA.8 review

Part A of the QA.8 review of the harness (`review-records/harness/qa8-part-a.md`) read the pre-action guard, `govharness/hooks/guard.py`, and found seven High findings (H1 to H7), seven Medium (M1 to M7), and three Low (L1 to L3). Each High or Medium reproduction is a `Bash` call that the guard let through with no outcome: a comment or a joined line hid the next command (H1); a git alias hid a push or a rebase (H2); an unquoted here-document's substitutions ran unseen (H3); a line could make the guard run past the hook's timeout, which lets the call proceed (H4); `xargs` fed a command (H5); `l/..` after a symbolic link was resolved lexically (H6); a pattern in a write target matched the ledger or `.git` (H7); options moved the real operand (M1); setuid modes in other spellings (M2); remote writes in other spellings (M3); store reads by other programs (M4); write destinations of other programs (M5); destructive git forms (M6); and no test held any of these (M7). This unit fixes all of them, and the three Low findings.

The design rules of the brief: where the guard cannot read a construct soundly it refers the call, never lets it through; ordinary agent commands still reach no outcome; the guard answers within its own budget, and under the assured profile a call that is too large is referred or refused, never left with no outcome (STND.HARN.23).

## Definition of done

1. Every reproduction of H1 to H7 and M1 to M6 in the report reaches an outcome, refused or referred. Each is a test, with the reviewer's exact input, and each test fails on the guard as it was before this unit (M7).
2. Where the guard cannot read a construct soundly, it refers the call. No such construct proceeds.
3. The guard has a bound on the work of reading one call (paths resolved, time, nesting), checked in the loops that grow. Past it the call is referred as too large to read, well inside the hook's timeout of 10 s. Under `--assured` the answer is `ask`, or `deny` unattended, never none.
4. Ordinary agent commands reach no outcome, and a test holds it. Where a fix refers something common, this record says so.
5. L1 to L3 are fixed, or this record says why not.
6. The module docstring, `COVERAGE_TABLE` (rendered as `coverage.md`), and `harness/README.md` say what is read and what is referred, and claim no more.
7. `tests.hooks.test_guard`, `tests.hooks.test_remote_writes`, `tests.derive.test_environment`, `tests.derive.test_authorizations`, `tests.test_architecture`, and `tests.test_conventions` pass. `python3 -B -m govharness verify governance` passes. ## Record

The shell's behavior behind H1, H6, and H7 was checked in a scratch directory, `/tmp/claude-1000/unit-0015/shell/`, by the script `/tmp/claude-1000/unit-0015/shell-checks.sh`. It confirmed that bash runs the line after a comment; prints `a#b`, `$#`, and `${#x}` as words; joins `ec\<newline>ho`; removes `\<newline>` inside double quotes but keeps it inside `$'...'`; ends a comment at the newline even after a backslash; and reads `w\<newline>#x` as the word `w#x`. ### High

- **H1, comments and joined lines.** `lift_heredocs` already tracked quotes and where a comment starts. It now also makes the line plain for the lexer: it drops a comment, from a `#` that begins a word to the end of its line, and it removes a backslash before a newline outside single quotes and `$'...'`. Whether a `#` begins a word is now judged by the last character kept, not the character before it in the text, so `w\<newline>#x` is one word, as in bash. `split_commands` sets `lexer.commenters = ""`, so a `#` left in the line is part of a word (`a#b`, `$#`, `${#x}`). A `#` inside `${...}` or arithmetic starts no comment. Tests: `CommentsAndContinuations` (the reviewer's ten inputs, and a quoted `#` and a quoted joined line that stay text).
- **H2, git aliases.** `check_git` refers every subcommand that is not in `GIT_COMMANDS`, the commands of git 2.56 (`git help -a`). Git ignores an alias that has the name of one of its own commands (git-config(1), `alias.*`), so every alias is such a subcommand: one that `-c alias.p=push` gives in the call, and one that `git config alias.p push` set in an earlier call. The same rule refers an external command such as `git lfs` and a misspelling that `help.autocorrect` would correct. A first draft also referred any `-c alias.*`, but a mutation showed it adds nothing to the subcommand rule, so it was dropped. `--config-env`, which takes a setting such as `core.pager` from a variable, is referred. `git config` is referred when it writes anything but a key of `CONFIG_PLAIN` (`user.name`, `user.email`, `init.defaultBranch`, `pull.rebase`, `pull.ff`, `color.ui`, `core.autocrlf`, `core.filemode`) in the repository's own file. Reads (`--get`, `--list`, one key alone, `get`, `list`) pass. A `-c` value is still read as a command line, as before. Tests: `GitAliases` (the reviewer's three inputs, the two-call form, `--config-env`, and plain settings and reads that pass).
- **H3, unquoted here-documents.** `lift_heredocs` reports each body whose delimiter has no quote or backslash. `check_line` reads each `$(...)` and backquoted span of such a body as a command line, after joining its continued lines, whatever program receives the body. A body whose delimiter is quoted is still data. Tests: `UnquotedHereDocuments` (the reviewer's five inputs; `<<'EOF'`, `<<"EOF"`, and `<<\EOF` reach nothing).
- **H4, the work bound.** `Scan.spend` counts resolved paths against `MAX_PATHS` (20 000) and checks the clock against a deadline of `TIME_BUDGET` (3 s) from the start of the call. It is called for each path that `resolve` produces and at each command line and simple command, so every loop that grows passes through it. Past either bound it raises `TooLarge`. `check_call` then adds `selective-destruction`, "command too large to read: more than N paths" or "more than 3 s", and returns, so the call is referred, or refused in an unattended session. `MAX_DEPTH` (64) bounds the nesting of command lines, by substitution or `bash -c`; a deeper call is denied as unreadable. That is what the review 0005 case of 2 000 nested `$(` got before, from a recursion fault after 3.3 s; now it gets it at once, and the earlier test is unchanged. `MAX_COMMAND` stays 100 000. A here-document's body is lifted out unread, so a 93 KB file written by one reads in 13 ms, and lowering the limit would refer such writes. The time per pass over the line part is bounded by the deadline. Measured with the reviewer's `slow2.py` input: 300, 1 000, and 2 500 operands after 15 `cd` words (10 KB to 83 KB) are referred in 0.5 to 1.6 s, where they took 6.7 to 53 s. ## Revision after review

This section supersedes the statements above where they differ. That covers the reading of an alias under H2, the outcome of `git reset` under M6, the counts under Checks, and the list of what is now referred.

The coordinator set a design rule for this pass. Each construct the guard reads by hand has more corners, so for comments, quoting, backquotes, `case`, and nested substitutions the guard now prefers a conservative backstop over more special cases. A line whose reading is uncertain is referred, as is a line where a second, simpler reading disagrees with the first about where commands begin.

- N1, a `#` after an escaped character: fixed. In `lift_heredocs` an escaped character is now part of a word, even a blank, so the `#` after `a\ ` starts no comment and the command after the `;` is read. Any `#` next to an escape pair is also recorded as a doubt, and the line is referred ("line not read soundly"). Test: `test_hash_after_an_escape`, with the reviewer's six inputs, each of which reaches elevated-privilege and is referred.
- N2, a comment in backquotes: fixed. `lift_heredocs` tracks the backquote, at the top level and inside double quotes. A comment inside one ends at the next backquote, as in bash. A comment inside a backquoted span or a `$(...)` is a doubt, and the line is referred. Test: `test_comment_in_backquotes`, with the reviewer's three inputs, plus `echo `ls # x`` and a multi-line `$(ls # x ...)`, each referred though read correctly. `echo `date`` still passes.
- N3, `case` in a substitution: fixed by referral. A `case` that begins a word inside `$(...)` or backquotes, at the top level or inside double quotes, is a doubt. In an unquoted here-document's body, a substitution span holding a comment or a `case` (`UNCERTAIN_RE`) is a doubt, since `substitutions` cannot find its end soundly. The regression came from `split_commands` going on with the interrupted command after a `)` (L2). That rule stays, and the doubt refers these lines. The second reading below also finds the `sudo` in each. Test: `test_case_in_a_substitution`, with the reviewer's five forms, the double-quoted form, `case` in a here-document, and `$(echo hi # )` in one.
- The second reading (design rule): `command_starts` reads the line, with its here-document bodies lifted and its comments kept. It knows only quotes, backslashes, comments (in backquotes ending at the next backquote), and where commands begin: after `;`, `&`, `|`, a newline, a parenthesis, a backquote, `$(`, and leading assignments and reserved words. `Scan.programs` records every program word the first reading reads. Where the second reading finds the first word of a command that is a program the guard knows (`KNOWN`), and the first reading never read it, the line is referred. This runs for every line read strictly, which excludes texts that a launcher's arguments may hold. Test: `test_second_reading`, which makes the first reading lose everything after a `#`, as a mistake in it would, and checks that `echo ok # note` followed by `sudo id` on the next line is then referred and reaches nothing else. It also checks the word list of a mixed line.
