# Unit 0015: guard fixes from the QA.8 review

Part A of the QA.8 review of the harness (`review-records/harness/qa8-part-a.md`) read the pre-action guard, `govharness/hooks/guard.py`, and found seven High findings (H1 to H7), seven Medium (M1 to M7), and three Low (L1 to L3). Each High or Medium reproduction is a `Bash` call that the guard let through with no outcome: a comment or a joined line hid the next command (H1); a git alias hid a push or a rebase (H2); an unquoted here-document's substitutions ran unseen (H3); a line could make the guard run past the hook's timeout, which lets the call proceed (H4); `xargs` fed a command (H5); `l/..` after a symbolic link was resolved lexically (H6); a pattern in a write target matched the ledger or `.git` (H7); options moved the real operand (M1); setuid modes in other spellings (M2); remote writes in other spellings (M3); store reads by other programs (M4); write destinations of other programs (M5); destructive git forms (M6); and no test held any of these (M7). This unit fixes all of them, and the three Low findings.

The design rules of the brief: where the guard cannot read a construct soundly it refers the call, never lets it through; ordinary agent commands still reach no outcome; the guard answers within its own budget, and under the assured profile a call that is too large is referred or refused, never left with no outcome (STND.HARN.23).

## Definition of done

1. Every reproduction of H1 to H7 and M1 to M6 in the report reaches an outcome, refused or referred. Each is a test, with the reviewer's exact input, and each test fails on the guard as it was before this unit (M7).
2. Where the guard cannot read a construct soundly, it refers the call. No such construct proceeds.
3. The guard has a bound on the work of reading one call (paths resolved, time, nesting), checked in the loops that grow. Past it the call is referred as too large to read, well inside the hook's timeout of 10 s. Under `--assured` the answer is `ask`, or `deny` unattended, never none.
4. Ordinary agent commands reach no outcome, and a test holds it. Where a fix refers something common, this record says so.
5. L1 to L3 are fixed, or this record says why not.
6. The module docstring, `COVERAGE_TABLE` (rendered as `coverage.md`), and `harness/README.md` say what is read and what is referred, and claim no more.
7. `tests.hooks.test_guard`, `tests.hooks.test_remote_writes`, `tests.derive.test_environment`, `tests.derive.test_authorizations`, `tests.test_architecture`, and `tests.test_conventions` pass. `python3 -B -m govharness verify governance` passes. Ruff adds no finding on the changed files. `harness/governance/` is unchanged, and the reviewer's probes in `/tmp/claude-1000/qa8-a/` are not edited.

## Record

The shell's behavior behind H1, H6, and H7 was checked in a scratch directory, `/tmp/claude-1000/unit-0015/shell/`, by the script `/tmp/claude-1000/unit-0015/shell-checks.sh`. It confirmed that bash runs the line after a comment; prints `a#b`, `$#`, and `${#x}` as words; joins `ec\<newline>ho`; removes `\<newline>` inside double quotes but keeps it inside `$'...'`; ends a comment at the newline even after a backslash; and reads `w\<newline>#x` as the word `w#x`. With `l -> ../outside/deep`, `echo x > l/../evil` wrote `outside/evil`. `echo hi > ledger.json?` overwrote `ledger.jsonl`, and so did `ledger.jso[^x]l`, since bash reads `[^...]` as a negation. A redirection to a pattern with two matches fails as "ambiguous redirect". In an unquoted here-document, bash runs `$(...)` and joins `\<newline>`.

### High

- **H1, comments and joined lines.** `lift_heredocs` already tracked quotes and where a comment starts. It now also makes the line plain for the lexer: it drops a comment, from a `#` that begins a word to the end of its line, and it removes a backslash before a newline outside single quotes and `$'...'`. Whether a `#` begins a word is now judged by the last character kept, not the character before it in the text, so `w\<newline>#x` is one word, as in bash. `split_commands` sets `lexer.commenters = ""`, so a `#` left in the line is part of a word (`a#b`, `$#`, `${#x}`). A `#` inside `${...}` or arithmetic starts no comment. Tests: `CommentsAndContinuations` (the reviewer's ten inputs, and a quoted `#` and a quoted joined line that stay text).
- **H2, git aliases.** `check_git` refers every subcommand that is not in `GIT_COMMANDS`, the commands of git 2.56 (`git help -a`). The list leaves out commands that run a program or a server, or read a credential (`credential*`, `daemon`, `instaweb`, `http-backend`, `hook`, `for-each-repo`, `svn`, `p4`, the `cvs*` and `*import` scripts, `imap-send`, the GUIs), so they are referred too. Git ignores an alias that has the name of one of its own commands (git-config(1), `alias.*`), so every alias is such a subcommand: one that `-c alias.p=push` gives in the call, and one that `git config alias.p push` set in an earlier call. The same rule refers an external command such as `git lfs` and a misspelling that `help.autocorrect` would correct. A first draft also referred any `-c alias.*`, but a mutation showed it adds nothing to the subcommand rule, so it was dropped. `--config-env`, which takes a setting such as `core.pager` from a variable, is referred. `git config` is referred when it writes anything but a key of `CONFIG_PLAIN` (`user.name`, `user.email`, `init.defaultBranch`, `pull.rebase`, `pull.ff`, `color.ui`, `core.autocrlf`, `core.filemode`) in the repository's own file. Reads (`--get`, `--list`, one key alone, `get`, `list`) pass. A `-c` value is still read as a command line, as before. Tests: `GitAliases` (the reviewer's three inputs, the two-call form, `--config-env`, and plain settings and reads that pass).
- **H3, unquoted here-documents.** `lift_heredocs` reports each body whose delimiter has no quote or backslash. `check_line` reads each `$(...)` and backquoted span of such a body as a command line, after joining its continued lines, whatever program receives the body. A body whose delimiter is quoted is still data. Tests: `UnquotedHereDocuments` (the reviewer's five inputs; `<<'EOF'`, `<<"EOF"`, and `<<\EOF` reach nothing).
- **H4, the work bound.** `Scan.spend` counts resolved paths against `MAX_PATHS` (20 000) and checks the clock against a deadline of `TIME_BUDGET` (3 s) from the start of the call. It is called for each path that `resolve` produces and at each command line and simple command, so every loop that grows passes through it. Past either bound it raises `TooLarge`. `check_call` then adds `selective-destruction`, "command too large to read: more than N paths" or "more than 3 s", and returns, so the call is referred, or refused in an unattended session. `MAX_DEPTH` (64) bounds the nesting of command lines, by substitution or `bash -c`; a deeper call is denied as unreadable. That is what the review 0005 case of 2 000 nested `$(` got before, from a recursion fault after 3.3 s; now it gets it at once, and the earlier test is unchanged. `MAX_COMMAND` stays 100 000. A here-document's body is lifted out unread, so a 93 KB file written by one reads in 13 ms, and lowering the limit would refer such writes. The time per pass over the line part is bounded by the deadline. Measured with the reviewer's `slow2.py` input: 300, 1 000, and 2 500 operands after 15 `cd` words (10 KB to 83 KB) are referred in 0.5 to 1.6 s, where they took 6.7 to 53 s. A 90 KB quoted line with 15 `cd` words reads in under 0.5 s and still finds the `sudo` after it. Under `--assured` the answer is `ask` attended and `deny` unattended. A signal alarm in `main` was considered as a backstop and not used: decision 0001's table of effects lets no module change the interpreter's state, and the bound already runs in every loop that grows. Tests: `WorkBound` (the reviewer's 300-operand input is referred for its paths within `TIME_BUDGET + 2` s; a clock made to pass the deadline refers `ls; ls`; `main --assured` answers `ask`, or `deny` unattended).
- **H5, xargs.** `xargs_command` reads GNU xargs' options and their values (`-I`, `-i`, `--replace`, and those that take a value), and returns the program and the replace string. `check_xargs` refers the command when the replace string occurs in the program word, when the program removes or moves (as before), and when the program is not in `XARGS_READERS`, the readers and text programs plus `basename`, `dirname`, `readlink`, and `realpath`. The command as written is then read as before. The replace-string check is not redundant: with `-I at`, `xargs -I at cat u+s f` runs `chmod u+s f`. Tests: `XargsCommands` (the reviewer's four inputs and the `-I at` case; `xargs grep -l`, `xargs wc -l`, and `xargs -I{} echo {}` pass).
- **H6, `..` after a link.** `named_paths` returns the lexical path and, where a `..` follows a symbolic link, the path `os.path.realpath` gives for the joined path before normalizing. That is where the system resolves it. `resolve`, and the file tools through `tool_paths`, check both. The reviewer offered a referral as well. This fix reads the construct soundly instead: as the link stands at the check, each outcome is the one the write reaches. A link made in the same line, or changed after the check, is the gap the coverage text already states. `cd l/..` adds both directories, since bash's `cd` is lexical. Tests: `LinkThenParent` (the reviewer's four inputs in a temporary work, and the Write tool, reach write-bounds; `sub/../notes.txt` without a link passes).
- **H7, patterns in write targets.** `check_writes` sends a pattern to `check_pattern_written`. That checks the pattern's base directory as a write, then each outcome of a protected name the pattern may match: a configuration location (`may_select`, part by part, where `**` matches any depth), any part that may match `.git` (history-rewrite), a ledger name, unless the write only appends (record-entries), and the store. `matches` reads `[^...]` as the shell's negation, a mistake that `check_pattern`, for removals, also had and now shares the fix for. `fnmatch`'s `*` also matches a leading dot and a slash, so the reading may say a pattern matches where the shell does not, never the other way. This is precise rather than a blanket referral of every pattern write. A referral would ask about `chmod +x scripts/*.sh` and `sed -i ... src/*.py`, and the over-reading already gives the protected names their own refusals. Tests: `PatternWrites` (the reviewer's five inputs, `ledger.jso[^x]l`, and `.cl*` reaching enforcing-configuration; the two ordinary forms pass).

### Medium

- **M1, operand positions.** `script_files` reads a program whose first operand is its script or pattern unless an option gives one, by a `Syntax` of its options: short ones that give the script, take a value, or take an optional joined value, and long ones (abbreviations count). It serves `sed`, `perl -i`, `awk`, `grep`, and `rg`, so `sed -i -es/a/b/ FILE` and `--expression=` keep `FILE`, and `sed -i '/x/d' f` does not read `/x/d` as a path. `mode_and_files` reads chmod, chown, and chgrp: the mode is the first argument that is not an option of theirs, so `-w` counts as a mode, and with `--reference` every such argument is a file. Tests: `OperandPositions` (the reviewer's three inputs; `sed -i '/x/d'` with and without `-e` passes).
- **M2, setuid modes.** `grants_privilege` takes the mode. An octal mode of any length sets privilege when it has bit 04000 or 02000. A symbolic mode sets it when any `+` or `=` in it is followed by `s`. Tests: `SetIdModes` (the reviewer's three inputs; `755`, `u+x,go-w`, and `-w` pass).
- **M3, remote-write spellings.** `option_values` reads short clusters, joined values, `--name=value` and `--name value`, and abbreviations of three characters or more. `check_curl` uses it with `CURL_VALUED`: `-d`, `-F`, `-T`, `-K`, `-Q`, and their long forms, `--form-string`, `--json`, `--mail-rcpt`, and a method other than GET or HEAD are remote writes. Its output options are writes (M5). `ssh` fed by a pipe, a redirection, or a here-document is a remote command. `CONNECTORS` (`nc`, `ncat`, `netcat`, `socat`, `telnet`) are always referred. `check_gh` refers every command of gh outside `GH_READS` and `GH_READ_COMMANDS`, a list of reads (`pr view`, `run list`, `auth status`, and others), and keeps the authorized posts of unit 0008. `PUBLISHERS` adds poetry, uv, flit, hatch, gem, mvn, gradle, podman, and helm. A publisher's arguments are also searched as a launcher's are, so `uv run rm -rf ...` is still read. `git send-email` and `git send-pack` are remote writes. `git lfs push` is referred under H2. Tests: `RemoteSpellings` (the reviewer's sixteen inputs; plain curl GETs with `-sSL`, `-fsSLo`, `-I -H`, `gh pr view`, `gh run list`, `gh auth status`, and `ssh -T` pass).
- **M4, store reads.** `READERS` gains base64, the checksum programs, `od`, `hexdump`, `strings`, `nl`, `tac`, `rev`, `cmp`, `comm`, `paste`, and the `z`, `bz`, and `xz` readers. `tar` left the list for its own check. `xxd` stays out, since `xxd IN OUT` writes `OUT`. `check_search` reads the files of grep and rg, and a recursive search (rg's always is) takes in the store as the Grep tool does (STND.DFLT.31). Non-in-place `sed` and `awk`, and `sort`, read their files, `dd if=` is a read, and `install` reads its sources as `cp` does. `find` with `-exec` or `-ok` reaches read-bounds where a root holds the store. `tar` creating an archive reads its members, and `rsync` reads its sources, each with `check_copied`, so a copy of the store is seen. Tests: `StoreReads` (the reviewer's ten inputs in a temporary work with a store holding `key`, closed, and `token`, opened; `grep x secrets/token` passes).
- **M5, write destinations.** The destination is checked for `rsync` (a local last operand), `tar` (the archive it creates, and `-C` or the working directory for an extract), curl's `-o`, `-D`, `-c`, and long output options, wget's `-O`, `-o`, `-a`, and `-P`, `sort -o`, `uniq IN OUT`, the compressors (each operand, unless `-c`, `-k`, `-l`, or `-t`, and the name without its suffix when decompressing; zstd keeps by default), `find -fprint`, `-fprint0`, `-fls`, and `-fprintf`, `git init`, `git clone` with a directory, `git worktree add`, `git archive -o`/`--output`, and the file of `git config --file`, `--global`, and `--system`. A tar option that runs a program (`--to-command`, `--checkpoint-action`, `--info-script`, `--new-volume-script`, `--rsh-command`, `-F`) is referred. A compressor that `-I` or `--use-compress-program` names is read as a command. Tests: `WriteDestinations` (the reviewer's twelve inputs reach write-bounds, and `gzip /srv/work/ledger.jsonl` reaches record-entries).
- **M6, git forms.** `dry_run` is false where any `--no-...` option is given, as `--no-dry-run` undoes `-n`. `restore` overwrites files unless `--staged` is given without `--worktree` (or `-S` without `-W`). `check_reset` reads the first operand before `--`. `HEAD`, `@`, or none passes. A commit written with `~`, `^`, `@`, or an object name moves the branch, so it is history-rewrite. A plain name may be a path or a branch, so it is referred. `--hard` stays selective-destruction. `branch -m` and `--move` are history-rewrite, as are `symbolic-ref` with two operands or `-d`, and `fast-import`. `history` and `replay` join `HISTORY_REWRITES` too. Tests: `GitDestructiveForms` (the reviewer's six inputs; `git reset`, `git reset HEAD file.txt`, `git reset -- file.txt`, `git restore --staged file.txt`, and `git symbolic-ref HEAD` pass).
- **M7, tests.** 29 tests were added to `tests/hooks/test_guard.py`, from `CommentsAndContinuations` to `OrdinaryWork`. Each reproduction of the report is a subtest of its own, with the reviewer's exact input. Run against the guard as it was at the start of this unit (a copy with only its import changed), every reproduction subtest fails, and `test_too_many_paths_is_referred` and `test_deadline_is_referred` error.

### Low

- **L1, CDPATH.** Fixed. `SET_VARIABLE_RE` also finds `CDPATH`, and `enter_directory` makes a `cd` to a relative name, after a line that sets it, a directory the guard cannot tell, so each relative path is computed. The reviewer's line was already referred before this unit, but only because a relative `cd` read again on each pass grows the directories to `MAX_DIRECTORIES`, which makes the last one unknown. `test_cdpath` therefore also holds the rule on one `cd`.
- **L2, sourcing.** Fixed. `source` and `.` are read as a shell running a script. A script named as standard input (`/dev/stdin`, `-`, `/dev/fd/0`) is read from the here-string, here-document, or pipe that feeds it, so `. /dev/stdin <<< 'sudo id'` reaches elevated-privilege. A process substitution leaves the computed word `PROCESS_FILE` in the command it is part of, so `bash <(...)` and `source <(...)` run a computed script and are referred. For this, `split_commands` now continues the command that a `(` interrupted after its `)`, so `diff <(sort a) <(sort b)` keeps both files in `diff`, and `echo $(ls) foo` keeps `foo` an argument rather than a command. Test: `test_sourced_and_substituted_scripts`.
- **L3, coverage text.** Fixed. The module docstring now lists what is read, what is referred because it cannot be read soundly, and what is not seen. `COVERAGE_TABLE` names the forms read, the referrals of H2, H4, H5, and L2, the destinations of M5, the readers of M4, and the remote writes of M3. The condition on the timeout says that the guard refers a call it cannot read within its bound, and that only a guard the machine stalls past the timeout lets the call proceed. The README's list of what is not yet built has an item on the guard.

### Ordinary work

`OrdinaryWork.test_ordinary_commands` holds that these reach no outcome: multi-line scripts with comment lines, a comment after `cd`, `grep -rn`, `sed -n`, a plain `curl` GET, `git status`, `git log`, `git diff`, `git add && git commit`, Claude Code's commit form with a quoted here-document, a quoted here-document holding `$(sudo id)`, `rm build/a.o build/b.o`, `rmdir build`, `cp` and `cp -r` within the work, arithmetic followed by a comment, `tar czf` to `/tmp`, and `uv run pytest`. Other tests hold the passing forms named under each finding. `rm -r build` stays referred, by STND.INSTR.4, as before this unit.

These fixes now refer, or refuse, something an agent may do in ordinary work:

- a `git config` write of any key outside `CONFIG_PLAIN`, and every write with `--global` or `--system` (which also reaches write-bounds, as the sandbox would refuse it);
- `git reset NAME`, where the name may be a path (`git reset file.txt`; `git reset HEAD file.txt` and `git reset -- file.txt` pass). `git reset HEAD~1` and `git reset --soft HEAD^` are now refused as history-rewrite;
- a git alias of the user's (`git st`, `git co`), and an external command such as `git lfs`, `git subtree`, or `git flow`;
- `xargs` feeding any program outside the readers, such as `xargs sed -i` or `xargs python3`;
- a command of gh outside the list of reads, such as `gh pr ready` or `gh repo fork`, and `nc`, `socat`, or `telnet` in any form;
- a shell or `source` given a script by an unknown variable (`bash "$script"`); `source .venv/bin/activate` and `source ~/.bashrc` pass;
- a process substitution as a write target (`tee >(...)`, `exec > >(tee log)`);
- where a store holds a closed file, `grep -r` or `rg` over a directory that holds it, as the Grep tool already was;
- a write target pattern whose last part may match a ledger's name, or any part `.git` or a configuration location, such as a bare `*` (`sed -i ... *` is refused, since `fnmatch`'s `*` also matches `.git` and `.claude`), as `rm *` already was.
