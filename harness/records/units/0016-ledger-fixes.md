# Unit 0016: ledger fixes of QA.8 part B

The QA.8 review of part B (`review-records/harness/qa8-part-b.md`) read the ledger, core, cli, workflows, derive, and query packages and found 3 High, 6 Medium, and 8 Low findings. The High findings are a ledger that one text character makes unreadable for good (H1), a ledger rewritten without signatures that passes once `SIGNR` is removed although the owner's configuration names an anchor (H2), and a tail of the ledger that can be cut with `verify` still passing (H3). The Medium findings are a key closed for a ledger that stays valid through an `all` row (M1), `record_transaction` writing manifests before the ledger refuses the entry (M2) or appending an unsigned entry that the register requires to be signed (M3), a pin that goes stale when a later scope covers the same directory with other paths (M4), a scope hash that two sets of files can share (M5), and signature rules that no test holds (M6). This unit fixes every High and Medium finding, and L1, L2, and L5. The harness follows the corpus as written: where a fix the review proposed reads STND.HARN otherwise (M1, M4), the harness keeps the letter and refuses, before any write, the step that would leave the corpus failing, and the wording is left to the custodian (Open).

## Definition of done

1. H1: a ledger line ends at a line feed only, so an entry whose text holds U+2028, U+2029, or U+0085 reads back whole, and `append` refuses a line that does not read back as the entry. A test covers each of the three characters.
2. H2: where the signer configuration names an anchor and the corpus has no `SIGNR`, the ledger check of `verify` fails, and so does every reader that trusts the ledger through it.
3. H3: the signer configuration may pin the head of the corpus ledger (`seq` and `hash`). `verify` and `sign check` fail when the ledger lacks that entry. The README states the residual without a pin. A missing or empty ledger fails where the corpus holds content to pin. No file is written under `/etc`, and no owner configuration is created; the tests build or patch one.
4. M1: as the term Accepted signature reads, an open `all` row accepts the key on every ledger. The register helpers refuse a row of one ledger, or its closing, for a key and role label that an open `all` row names, citing STND.HARN.10, and the register's docstring no longer says that an `all` key is closed per ledger.
5. M2: `record_transaction` writes nothing before every refusal that `append` can raise has been checked. A test compares the whole tree after each refusal.
6. M3: an unsigned entry that the register requires to be signed is refused, naming `ledger append --sign`, and a register transaction is refused while the register has problems.
7. M4: a pin holds until the next transaction of the same scope tuple, as STND.HARN.9 reads. A transaction that would leave the pin of another tuple stale is refused before any write, naming that tuple, so that no valid `record_transaction` leaves the corpus failing `verify`; both of the review's cases are refused, with the tree compared. The live corpus still verifies.
8. M5: the scope hash is unambiguous, and every hash recorded in the live ledger stays valid.
9. M6: a test kills each surviving mutation the review lists, and each mutation, rerun on a scratch copy, fails a test.
10. L1, L2, and L5 are fixed where cheap; the other Low findings are listed with the reason they are not done.
11. The tests of what changed pass, with `tests.test_architecture` and `tests.test_conventions`. `verify governance` passes on the live corpus with its ledger unchanged. Ruff adds no finding on the changed files. The README describes each change of behavior. `harness/governance/` is unchanged.
