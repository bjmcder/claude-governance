# Unit 0010: unsigned authorizations

The security verification of unit 0008 (`review-records/round-2026-10-24/harn-auth/verify-security.md`, M-c) found that a signature is required for an authorization only where the work is assured or the corpus holds a signer register. Without a register, an agent is able to append to the ledger an unsigned `authorize` that names the human owner as actor, and to recompute the chain, since appends are permitted writes; `environment --authorization ID` then accepts it, and the printed summary is the only control. The custodian directed on 2026-10-24 that this be closed now, as a small unit. This unit refuses the derivation in that case unless the owner states, by an option, that it accepts the authorizations unsigned. The other residual of M-c, a default expiry horizon (M-b of `OPEN-ITEMS.md`), is not in scope.

## Definition of done

1. `environment` takes `--accept-unsigned`. Where `--authorization` names an authorization, the work is not assured, and the corpus holds no signer register, the derivation without the option exits 1, writes nothing, and prints the reason, beside every other reason of STND.HARN.29; it raises no uncaught exception.
2. There, with the option, the derivation proceeds as before, and the summary prints, for each authorization relied on, a line that it was accepted unsigned.
3. Where the work is assured or a signer register exists, a signature that the register verifies is required as before; the option has no effect, and the reason of a refusal says so.
4. Each criterion has a test; every earlier test passes; ruff at 79 columns adds no finding on the changed files.
5. The README and decision 0002 record the change, and this record states whether STND.HARN.29 needs an amendment.

## Record

- Done: `ACCEPT_UNSIGNED` and the parameter `accept_unsigned` of `read_authorizations` and `record_problems` (`derive/environment/authorizations.py`). Where no signature is required (`signed` false) and the owner did not accept, `read_authorizations` adds one reason naming the authorizations and the two ways on (found a signer register, or pass the option), so the command's existing handler of `ValueError` prints it and exits 1 before any file is written. With the option, each summary line of an authorization relied on is followed by `ID: accepted unsigned (--accept-unsigned): ...`. Where `signed` holds, the option changes nothing but the wording of the signature reason, which adds that the option has no effect where the work is assured or a signer register exists. The option `--accept-unsigned` (`cli/environment.py`), passed through by `authorized`. The README's environment row and its bullet on remote writes, and an adjustment table for this unit in decision 0002.
- Tests, in `tests/derive/test_authorizations.py`: the class `Unsigned`, with `test_refused_without_register` (no register and no option: refused with the reason, and beside a reason of the provision), `test_accepted_with_the_option` (accepted, and the summary says so), `test_signature_required_regardless` (a register or assured work: unsigned or unverified is refused with the option and the reason says it has no effect; a verified signature is relied on and no acceptance line is printed), and `test_command_refuses_and_accepts` (the command: exit 1 and nothing written without the option; exit 0 and the summary line with it; exit 1 with `--assured`). The helper `reading`, used by the tests of the rows of STND.HARN.29, accepts unsigned by default, so that each of those tests still tests its row alone; `full_reading` returns the summary too. `test_command_option` now passes `--accept-unsigned`, and with a signer register present it asserts that the signature is still required and that the option has no effect. Each of three changes to the code fails a test (checked by patching each in turn): dropping the refusal (two tests fail), dropping the summary line (two), and letting the option lift a required signature (five).
