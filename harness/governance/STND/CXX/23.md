Code that accesses an object from more than one thread, interrupt handler, or signal handler SHOULD order each conflicting access by an atomic operation, by a synchronization facility of the standard library or of the target, or by a facility of a library whose contract states its ordering (DSGN.15, HW.11). Where no synchronization facility of the target orders the accesses to an object that a signal or interrupt handler shares with the code it interrupts, that object SHOULD be a lock-free atomic object or, for a signal handler, an object of type volatile std::sig_atomic_t (DSGN.15).
