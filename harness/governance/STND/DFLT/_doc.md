## Purpose and scope

This standard provides the mechanisms of GOV.21, and the ledger of GOV.36, for work without a project constitution (GOV.22). It also gives the vocabulary of access descriptors that AGENT.23 leaves to the defaults, and the locations of the workbench and, where the human owner provides one, of the store of non-credential secrets, which AGENT.35 and AGENT.44 leave to the project. Every provision is binding, because it instantiates GOV.22 (GOV.10), and none applies once a project constitution defines its own mechanisms. No provision grants an authorization, adopts a hazard analysis, sets a class, authorizes an estimate (GOV.22), or sets a time limit: STND.DFLT.17 is the route by which an act of the human owner, given to an agent directly, reaches the ledger, and STND.DFLT.33 names the act of the human owner that authorizes an agent's operating cost; the act is the human owner's in each case.

## Normative and informative parts

The body of a numbered provision, including its table, is normative. Everything else is informative.

## Terms

This section fixes meaning and imposes no obligation, as the Lexicon does. Asset has the meaning that STND.THRT gives it.

| Term | Definition |
| --- | --- |
| Assured work | Work for which an entry that names the human owner as actor, or that records an act of the human owner under STND.DFLT.17, records CSQ0 or CSQ1 as the consequence class, the signer register lists a key of the human owner for the work's ledger, and no entry later than that classification that STND.DFLT.23 accepts for assured work records a less severe class. |
| Attempt without progress | A change to or run of the work, checked against the acceptance criteria, after which no more criteria are met than at the best earlier point of the unit of work. |
| Bulk item | A file, a listed object of a remote store, a database row, or a message; a directory counts as its contents. |
| Checkpoint | A copy of an item's prior state that the provisioned environment keeps outside the scope of an action before the action changes or removes the item. |
| Destructive action | An action that removes or overwrites an item, or alters it other than by appending. |
| Operative | Of a configuration or mechanism that an entry records: found in the current session to be installed as the entry states; for assured work, found so by a verifier that the agent is unable to alter. |
| Session | One continuous run of an agent and the instructions it received in that run. |
| Signer register | The register SIGNR of keys, each listed for the ledgers it signs, against which the harness verifies signatures. |
| Temporary location | A directory created empty for intermediates, or for working copies of items whose source lies outside the work, recorded as temporary at creation, outside "records" and the version-control metadata. |
| Tool memory store | A store of an agent's notes that a tool of the agent keeps outside the work and across sessions, at a location that a record of the work names, holding no secret and no other data that the threat model protects against disclosure (PRIME.10), and lying within the working bounds for that agent. |
| Working bounds | The locations, network domains, and retrieval scopes that a configuration the agent is unable to alter, or an entry that STND.DFLT.23 accepts, opens to an agent; by default, the top directory of the work, each temporary location, each file and directory that the agent or its run creates in the system's temporary directory, and each location in which installed software keeps its caches, state, or configuration by the convention of its operating system or tool, and for reading also the installed software and the account's files; the default leaves out, for writing, each configuration that settles the tier of an agent's actions or otherwise governs an agent (GUARD.2, PRIME.7), each instruction file (STND.INSTR), and each setting that enables a check of security or integrity, selects a source or destination of network access, or runs a program without a request; and it leaves out altogether the store of AGENT.44, each location that holds secrets or credentials by the convention of its operating system or tool, and each location that the threat model or an entry that STND.DFLT.23 accepts names as holding secrets, credentials, or other data it marks as protected (PRIME.10). A domain is within the bounds only with the purpose and volume an authorization names (GUARD.13). A file of the directory of STND.DFLT.29 is within the bounds only for an agent that an authorization permits to handle the secret that the file holds (PRIME.10). |

## Notes

An unlisted destructive action is a bulk action and reserved (GUARD.6); listing removes only that status, and each item still needs an exempt class (GUARD.5). The fourth class rests on GUARD.7 as LVL0 1.5 amended it. Command-level practice, such as shell guards and dry runs, belongs to STND.INSTR (STND.INSTR.4, STND.INSTR.5). For a build, an install, or a test run, the configuration that the work records for it under version control gives the list of STND.DFLT.24 (STND.DFLT.34): the locations it names as written, an output directory counting as its contents, with the locations in which the run's tools keep their caches and state, each with symbolic links resolved; version control keeps the configuration reviewed and readable before the run, and regenerable outputs fall in the third exempt class (GUARD.7). The custodian ruled on 2026-10-28 that "builds, installs, and tests in the context of the project development" are permitted "if done against the stated configuration or otherwise authorized", and that "installation of new packages or any builds/tests beyond the project bounds" halts and is referred; the stated configuration is read as the configuration that the work records under version control, and the project bounds as the working bounds. A change to the recorded configuration that adds a package or a source, or changes the pinned revision of a package, is itself the installation of a package the configuration did not name, so STND.DFLT.35 halts and refers the addition unless an authorization covers it or the human owner gave it directly, and STND.DFLT.34 never reaches an install of what an agent added on its own; an install that retrieves a package from outside the provisioned environment is also network access, which needs its own authorization (GUARD.13); STND.DFLT.25 holds the halt for a run beyond the working bounds. The first exempt class of STND.DFLT.15 names the last committed state of a file under version control as its recoverable prior state, and reaches a file only where it differs from that state by the agent's own changes in the current unit of work, so that an agent's successive edits of a file are not each a reserved overwrite (GUARD.5) while the uncommitted changes of another actor stay protected (STND.INSTR.2).

No class is set by default (GOV.13), so the rows of STND.CLASS.18 and STND.CLASS.19 have no occasion to act until the human owner records one. A project without a project constitution promotes a result only through its adopted classification (GOV.20), so its work is relied upon beyond its author only as QA.11 admits for work of CSQ3 or CSQ4.

An allow rule in a configuration is not an authorization unless an entry that STND.DFLT.23 accepts adopts it with the content of STND.DFLT.16, and never for an irrevocable remote write (GUARD.11). The direction of the human owner that STND.DFLT.33 names is the authorization of PRIME.8 for the operating cost of the units of work it covers; the estimate that the plan of a unit states under AGENT.6, where the cost is measurable, is the one against which that cost is monitored (GUARD.14), and a cap adopted under STND.DFLT.26 bounds it where one exists. The direction is the human owner's own act, entered under STND.DFLT.17, so no default authorizes an estimate (GOV.22); acceptance is never implied (PRIME.7), and a direction accepts a plan only where it says so.

Only for assured work does an entry need a signature (STND.DFLT.23) or a configuration displace a provision (STND.DFLT.22); elsewhere a configuration may fail open, so every provision stays in force. No class is assumed (GOV.13): an entry of the human owner, or an agent's entry of the human owner's act under STND.DFLT.17, that records CSQ0 or CSQ1 makes work assured once the signer register lists a key of that owner for the work's ledger, and only a signed entry then ends that; until the register is founded, the class stands as recorded, every entry of the human owner is accepted (STND.DFLT.23), and each referral names the founding of the register as a recommended next step (STND.DFLT.20), so that no project is locked by an entry it is unable to follow. A forged entry recording CSQ0 or CSQ1 before the register makes the work assured once the owner's key is listed, and a signed entry of the owner then ends that, so nothing locks. For other work, STND.DFLT.5 and PRIME.7 bar a forged entry, but nothing detects one. The custodians found the signer register with a key whose fingerprint the human owner keeps as the anchor where the agent's account cannot write it; a signature binds to its ledger and position.

STND.DFLT.17 is the route by which each act that the human owner gives an agent directly, and that governance requires to be recorded, reaches the ledger: an authorization and its revocation (GUARD.10), a waiver (GOV.44), a ruling (GOV.3), the classification and its revision (GOV.24, STND.DFLT.13), a promotion (QA.11), a release (QA.10), an adoption (GOV.41), the adoption of an instruction file (STND.INSTR), the direction of STND.DFLT.33, a decision to continue halted work (STND.DFLT.9), a change of the stopping rule (QA.3), the choice of a cost discipline (GUARD.14), the replacement of a default (GOV.19), and a decision that raises the floor (GOV.11); a direction that governance does not require to be recorded is not entered. The actor of an entry is the one who appends it, and the actor of the act that the entry records is stated in the entry; an agent's entry quoting an act of the human owner therefore names the agent as its actor (STND.DFLT.5) and the human owner as the actor of the act, and where the act accepts a proposal, the entry quotes the proposal accepted. The agent grants, rules, classifies, and adopts nothing by entering the act (PRIME.7, GOV.49): the act is the human owner's, given directly, and the entry is its record, accepted for work that is not assured (STND.DFLT.23); for assured work, only a signed entry of the human owner is accepted. STND.DFLT.17 has an agent enter no act as the human owner's that the owner did not give it directly, and STND.DFLT.5 bars an entry in the human owner's name, the two ways an agent would grant itself an authorization (PRIME.7).

STND.DFLT.32 has the first referral for an action of a class of the table of STND.PROJ.3 propose each standing authorization of that table that the work needs, so that the human owner decides once; it cites the table and copies none of it, and PRIME.14 already has a referral recommend actions. STND.DFLT.19 halts for irreplaceable data, physical hardware, and an outside system written to, the cases in which the table of STND.DFLT.18 leaves a threat unnamed or unprotected; another asset new to the work, in the sense that STND.THRT gives the term, is a matter for the review of the threat model (GUARD.16) rather than a halt.

The working bounds admit for writing each temporary location, each file and directory that the agent or its run creates in the system's temporary directory, and each location in which installed software keeps its caches, state, or configuration by the convention of its operating system or tool, so that a compiler, a package manager, or a test run that writes its cache or state there proceeds without a referral; what others created in the system's temporary directory stays outside the bounds. Among the locations of configuration, the bounds leave out for writing whatever governs the agent: the configuration that settles the tier of its actions or otherwise governs it (GUARD.2, PRIME.7), its permission and instruction configuration among it, each instruction file (STND.INSTR), and each setting that enables a check of security or integrity, selects a source or destination of network access, or runs a program without a request, so that no write of an agent widens its own authority; an agent proposes a change to such a file or setting by a referral (PRIME.14), and the machine-local row of STND.PROJ.3 leaves the same settings out. A tool memory store lies within the bounds where its tool keeps it in a conventional location of state, and a file of it is no instruction file (STND.INSTR), so the exclusion of instruction files leaves it in; STND.DFLT.6 makes it part of the working-notes workspace, so it carries no instruction authority (INTPR.5) and is never the only record of what a reader needs (INTPR.13), and the record of the work that names its location is what lets a reviewer find it.

Access descriptor has the meaning AGENT gives it. A descriptor is a kind and an outcome joined by a colon, as in "retrieve:refused"; three kinds and three outcomes give nine descriptors from six words, and the list is closed. A refusal includes one that a cap, a paywall, a required credential, a rate limit, or a published access rule causes; a failure includes a timeout, a transport error, an item not found, or a refusal by the provisioned environment.

The workbench (STND.DFLT.28) sits with the other records, so that it is kept under version control and retained with them, as AGENT.35 and AGENT.36 ask; its tools, which are repaired in place, sit apart from its entries, which are never altered (AGENT.34), so that a reviewer and a check of alteration tell them apart.

The work keeps a store of non-credential secrets only where the human owner chooses to provide one, by an instruction or a ledger entry; STND.DFLT.29 to STND.DFLT.31 then apply, and otherwise ask nothing. The choice is the human owner's own and no provision asks for it (STND.DRAFT.42). Without a store, an agent that an authorization permits to handle such a secret writes it to no location (AGENT.44). Where provided, the store (STND.DFLT.29) sits at the top of the work, outside "records", "notes", and version control, as AGENT.44 asks; an authentication credential never enters it (AGENT.45). It holds working copies of the secrets that the work is authorized to use, one per file, so that the working bounds admit each file only to an agent authorized to handle its secret: such an agent reads and writes it without a referral, and every other agent that reaches for it halts and refers (STND.DFLT.25). The directory is a temporary location, as the term now admits for working copies whose source lies outside the work, so that removing a secret the work no longer needs, as AGENT.44 asks, is the removal of a temporary item (STND.DFLT.15) rather than a reserved action; for the same reason no record cites a file of the store, and a record names a secret by a description that is itself no secret. The store holds only working copies whose source is the grantor of the secret, so AGENT.37 is met. Before its first write in a session an agent confirms that version control excludes the directory and that no other unprivileged account reads it, restores either condition that fails, which is a reversible local action, and refers rather than writing only where it is still unable to confirm (STND.DFLT.30). Archives, backups, and transfers leave the directory out, so the archive of STND.DFLT.4 carries no secret, and recursive and pattern-selected operations skip it unless authorized for it, so that a search of the work neither reads a secret nor halts on one (STND.DFLT.31). A grant that contains a secret is entered in the ledger without that secret (STND.DFLT.17). A project constitution states its own locations, or adopts these by citation.

Locations that hold secrets or credentials by convention include the key directories of secure-shell and privacy-guard tools, the credential files of command-line clients for remote services, keyrings and password stores, shell history files, and browser profiles; an agent decides them by their path, without reading them (PRIME.10).
