## Answer in brief

1. A simulation race is a defect, not a variation. Two processes that read and write the same variable in the same region, with the result depending on the order the simulator happens to choose, are a race; the language leaves that order unspecified. Declared variation within a tolerance is no defect (STND.VVUQ.82); a true race is. [S1, S2]
2. Clocked storage is written with nonblocking assignment, combinational logic with blocking assignment, and no process mixes the two on one variable. No variable is driven by more than one process. A zero-delay workaround for a race is a defect to remove, not a fix. [S1, S2, S9]
3. A design is race-free by construction and checked by tools: a check names each variable with more than one driving process, each blocking assignment to clocked state, each delay in a combinational process, and each variable written by both assignment kinds. [S1, S9]
4. A testbench drives and samples the design only through a mechanism that the language gives for that purpose (a sampling edge before the clock event, a clocking construct, or the reactive regions), never by a delay chosen to win a race. [S1, S2]
5. Time-0 behavior is not relied on. No result depends on whether an initial block, an always block, or a declaration initializer runs first at time 0, and no clock is first driven at time 0 in a way that depends on that order. [S1]
6. A combinational process states its intent with the construct that the language provides for it, so that a tool checks that it infers no storage; a process that infers storage states that with its own construct. An incomplete sensitivity list, which simulates differently from the logic it synthesizes to, does not exist in a design. [S9, S15, S20]
7. A conditional or selection statement that is missing an assignment path states the result of every path. An inferred latch is a recorded design choice, never an accident. [S9, S15]
8. A simulation-only construct (an initial value in a synthesized state element excepted per HDES.12, a delay, a force, an unsynthesizable test of an unknown value) does not decide a behavior that the contract relies on. Where synthesis and simulation read a construct differently, the code uses a form that both read the same. [S6, S15]
9. Pragma comments that change what a tool synthesizes without changing what it simulates (full_case and parallel_case) are not used. The language's own qualifiers for exclusive and prioritized selection, checked in simulation, replace them, and a design does not use them where an unchecked branch changes the logic. [S6, S19]
10. A wildcard match on unknown or high-impedance bits is not used in synthesized selection. The wildcard form that matches only high-impedance bits, where used, carries a stated reason. [S15]
11. An unknown value is treated as two different things: a don't-care for synthesis and an unknown for simulation. The design record says where it assigns unknown values on purpose, and a check shows that each such assignment is unreachable or harmless, because a simulation that treats it as a known value masks bugs and a netlist simulation shows extra unknowns. [S15, S16, S17]
12. X-optimism and X-pessimism are both findings, with different remedies. An optimistic construct hides a defect in the description; a pessimistic one makes a netlist simulation disagree with hardware. Randomized or two-state initialization of state addresses pessimism and does not find optimism. [S15, S16, S17]
13. A reset is asynchronous or synchronous by recorded decision. Where it asserts asynchronously, its release is synchronized to the clock it releases (HDES.11); the verification includes assertion, release, and a reset during operation, not only a reset at the start of the run. [S1, S5]
14. A state machine has its states in one enumerated type, a defined behavior for each unused encoding, and a next-state function that assigns every state variable on every path; its verification covers every reachable state and transition, and its recovery from an illegal state is stated or its absence is. [S15, S19; shape from HDES.12, HDES.15]
15. A parameter is checked at elaboration: each admitted value is stated, and a value outside the admitted set stops elaboration with a message and is not silently clamped. A generate construct yields the same hierarchy for the same parameters in every tool. [S6, S11]
16. The synthesizable subset is a recorded input to the design (HDES.3, STND.DEPS.8). A design states which language revision and which constructs it uses, because the language definition does not define a synthesizable subset and the standard that did was withdrawn. [S6, S22, S23]
17. Verification constructs (classes, randomization, dynamic data, delays, program-style blocks, hierarchical references into the design) are kept out of files that are synthesized; a check lists every file in the synthesized set and every verification construct in it. [S1, S3]
18. An assertion states its clock, its disabling condition, and whether it checks in simulation, in proof, or both. An assertion that passes vacuously (an implication whose antecedent never occurs) is reported as vacuous, and the proof or simulation verdict is not read as pass for a property whose antecedent was never reached. [S2, S7]
19. A concurrent assertion reads sampled values and an immediate assertion reads current values; the verification record states which kind decides which property, and a property whose check depends on the sampling point is checked at that point in every simulator used. [S1, S2, S7]
20. Constrained random stimulus is reproducible from a recorded seed, and the seed is an input of each result (STND.CODE.9, STND.VVUQ.64). A change to unrelated code does not change the random stream of a process, or the record says it does; results are not compared across simulators on a seed. [S8, S13]
21. Functional coverage is defined from the contract (HDES.6), not from the stimulus; a coverage figure names its measure, its exclusions with a reason each, and whether it counted unreachable or unknown-valued branches. [S3, S15, S16]
22. Lint is a gate whose outcome is a list, empty or with each remaining finding waived by kind and source (HDES.9, STND.CODE.4). A finding about a latch, a width, a multiple driver, an incomplete selection, or a delay in clocked logic is resolved or explained. [S9, S15]
23. Equivalence of the description and the netlist is read with the unknown-value comparison mode named. A check in a mode that treats every unknown as a free choice passes designs whose simulations differ, so the record states the mode, and a failure in the strict mode that passes in the lax one is analyzed, not waived. [S5, S15; HDES.8, HDES.9]
24. The language tools are not assumed correct. A published bug study found incorrect netlists from random valid input in the synthesis tools it tested and wrong simulation in a simulator used to check; a project that depends on one result of a language tool checks it by a second route, as HDES.8 asks for the netlist. [S11, S12, S24]

Gaps in the existing corpus that the language standard may address, each at the cost of wording:

- **G1.** HDES.6 asks for coverage "by a measure that it names" but not what a measure counts when the description has unknown values. The language standard may ask that the record state it (S5).
- **G2.** HDES.12 verifies that a state element has a value; it does not say that a simulator-assigned initial value or a declaration initializer is evidence only for simulation. The standard may state that as a hazard in Notes and a provision on the evidence.
- **G3.** STND.CODE.4 says a repository configuration names static checks. It does not say that a check that a language tool offers for race-prone, latch-inferring, or width-truncating code is among those a hardware description names. The standard may state the classes (not the tool).
- **G4.** The edition and construct subset (answer 16) are not mentioned by HDES.3. This is a record, so it adds wording only under HDES.3 and STND.DEPS.8; no floor is raised.

## Timeless versus moving

**Timeless** (holds for any event-driven simulator and any revision):
- Zero-delay simulation serializes concurrent events; the order is unspecified; a design must not depend on it (answers 1 to 5).
- Hardware and simulation races differ; the second kind is removed by coding rule (S1).
- Unknown values have more than one meaning across simulation, synthesis, and equivalence; the choice of meaning decides what a pass shows (answers 11 to 12, 23).
- Simulation can pass what the netlist does not do, and the reverse (HDES.8, HDES.9).
- A seed makes a random result reproducible only if the stream is stable; stream stability depends on structure, not on the generator alone (answer 20).
- A language tool is software and has defects; a second route checks the one that matters (answer 24).
- A language with several revisions and tools that lag them needs a recorded edition and a recorded set of constructs (answer 16).

**Moving:**
- The exact list of constructs in the language, the 2023 enhancements, and the next revision.
- Which tools implement which constructs, and the extent of two-state versus four-state simulation.
- The names and options of lint, equivalence, formal, and synthesis tools, and the warnings they give.
- The version of the methodology library and its API fixes.
- Counts of tool bugs and respin shares.
- The status of the synthesis-subset standard, which could be replaced.

## Candidate shape of the standard (for the drafter)

Following STND.CXX: language edition in force and settings that change meaning (a recorded edition; two-state or four-state simulation; time precision); race-free coding as outcomes checked by tool (answers 1 to 5); intent-stating constructs (6 to 10); unknown values (11, 12, 23); reset verification (13, citing HDES.11, HDES.12); state machines (14); parameters (15); subset and verification constructs (16, 17); assertions (18, 19); random and coverage (20, 21); lint (22); tool defects (24). A provision's LVL0 ancestor is mostly VV.1, VV.5, VV.6, REPRO.3, INTPR.10, or DSGN.5, as in HDES; the first two provisions (race freedom, a recorded edition) can be defaults. The class onset follows HDES: from CSQ3, or CSQ2 where HDES.5 applies. These are suggestions for the drafting agent and are not rulings of the custodian. Whether any provision raises the floor is a decision for the custodian under GOV.11; none seems to, since each asks for a record or a check that HDES.6, HDES.8, HDES.9, or STND.CODE.4 already require at the same onset.
